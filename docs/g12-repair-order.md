# G12 Repair Order

Repairs are qualification-driven and follow dependency order.

1. G2: complete staged validation orchestration and diagnostics.
2. G3: complete distinct model semantics for Architecture, Workflow, Sequence, Data Flow and Lifecycle.
3. G4: add boundary/group-aware geometry, labels, collision checks, legend/viewport fitting while preserving deterministic hashes.
4. G5: render model-specific structures: architecture boundaries/groups, workflow lanes/phases, sequence lifelines/activations/segments, data-flow stages/stores, lifecycle lanes/transitions.
5. G6: wire browser pan/overview/fullscreen, focus/reach/route/lens/relationship inspection, deep-link restoration, six UI locales and export controls.
6. G7: harden repository dependency/runtime relationship evidence without executing repository code.
7. G8: qualify real PNG/WebP rasterization and browser clipboard/share behavior.
8. G9: run atomic delivery qualification against verified artifacts.
9. G10: run real browser desktop/mobile qualification with console capture, interactions, screenshots, visual checks and accessibility.
10. G11: make the executable CLI invoke real commands; extend compare to changed boundaries/evidence; qualify four adapters.
11. Performance: add and run benchmark fixtures for 100/500/1000 nodes, 5000 relationships, viewer load/search/focus.
12. Final G12 matrix: every row PASS with evidence, then and only then parity release.

No later repair may be used to waive an earlier failed gate.
